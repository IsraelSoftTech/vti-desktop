Accountant + consistency updates — algorithm
=============================================
Written: 2026-08-19
Status: spec — implement from this file
Scope: staff features on cloud API, web, mobile, and desktop.
       Parent access stays mobile-only (Part B of update.txt). Do not
       port parent login, barcode linking, parent chat, or parent fees
       to web or desktop.


Rules (locked)
--------------
1. SAME IMPLEMENTATION on mobile app, web, and desktop for every
   change in this file. One API contract. One field set. One
   validation rule. One print layout. If a behaviour exists for the
   accountant on one client, it exists on all three.

2. Desktop is the same web-front UI talking to the local Express +
   SQLite copy of mobile-back. Do not invent a second discount search,
   a second student form, or a second payment payload for Electron.

3. Parent role (attendance_parent) exists only on the mobile app.
   Staff features below never open the parent shell.

4. Cameroon clock stays Africa/Douala, HH:mm, amounts in the same
   currency formatter already used by fee screens.

5. Do not keep a platform fork “for now”. If desktop SQLite cannot
   run a Postgres idiom (ILIKE, NOT NULL on unresolved FK), fix the
   shared dialect / sync layer so all clients observe the same result.

6. SAME UI SCHEME on mobile, web, and desktop. Source of truth is
   the current mobile app (mobile-front theme + chrome). Web and
   desktop must use that palette, header, cards, buttons, fields,
   and light/dark toggle — not the existing web bright-blue look.
   New screens in this file ship in that scheme; existing staff
   screens are restyled to match. Print/PDF stays black-on-white.

PART A — Change password (accountant, and admin for lockstep)
========================================================

Staff must change their own password from the account menu on every
client. Accountant is the requester; admin uses the same control so
the account menu is not forked.

1. API (cloud Postgres AND desktop SQLite, same route)
------------------------------------------------------
  PATCH /api/attendance/me/password
  Auth: requireAttendanceAuth(attendance_admin, attendance_accountant).
  Parent is 403. Do not add this to the parent app in this spec.

  Body:
    currentPassword  string, required
    newPassword      string, required, min 6 characters
    confirmPassword  string, required, must equal newPassword

  Algorithm:
    1. Load attendance_users by token sub (id).
    2. bcrypt.compare(currentPassword, password_hash). Fail 400
       “Current password is incorrect.”
    3. Reject if newPassword === currentPassword
       (“New password must be different.”).
    4. bcrypt.hash(newPassword, 12). Save password_hash.
    5. Bump updated_at / row_version so desktop sync pushes the hash.
    6. Return { ok: true }. Do not return the hash.
    7. Keep the current JWT. Do not force logout.

  Desktop: the local user row is the source of truth offline. Outbox
  the users-table mutation. Next online push updates cloud. Password
  change must work with no internet.

  Do not sync a plaintext password. Only password_hash (already in
  sync COLUMNS.attendance_users).


2. UI (identical copy and fields on all three clients)
------------------------------------------------------

    Current password

PART B — Payment method: CASH or BANK
========================================================

The old free-text “Note (optional)” on a payment is replaced by a
required choice: Cash or Bank. Bank also requires a reference
number (free text, e.g. 001GC0). Accountant prints Cash and Bank
reports from the Reports page. The existing class fee list report
stays. Same on mobile, web, and desktop.


3. Persistence
--------------
  attendance_fee_payments.channel  TEXT NOT NULL DEFAULT 'cash'
    values: 'cash' | 'bank'

  attendance_fee_payments.note     TEXT  NULL
    Bank: the reference number (required, trimmed, kept as typed —
          letters, digits, e.g. 001GC0).
    Cash: NULL. Cash has no reference field.

  Postgres:
    ALTER TABLE attendance_fee_payments
      ADD COLUMN IF NOT EXISTS channel VARCHAR(8) NOT NULL DEFAULT 'cash';
    Existing rows → cash (historical unknown).
    Index (academic_year_id, channel, paid_at).

  SQLite desktop: same column, DEFAULT 'cash'. ensureColumn for
  already-created local DBs.

  Sync COLUMNS.attendance_fee_payments includes 'channel'.
  Do not invent a second “tender” table. Do not encode Cash/Bank
  only inside note — channel is its own column.

  mapPayment:
    channel: row.channel === 'bank' ? 'bank' : 'cash'
    note:    row.note || null          // bank reference, else null

  FeePayment on all clients:
    channel: "cash" | "bank"
    note: string | null                // reference when bank


4. Record / edit payment
------------------------
POST /fees/payments — channel is required.

  parse body.channel (case-insensitive) → cash | bank.
  400 “Select Cash or Bank.” if missing or invalid.

  Bank:
    reference = trim(body.reference || body.note).
    400 “Enter the bank reference number.” if empty.
    Store channel='bank', note=reference.

  Cash:
    Store channel='cash', note=NULL.
    Ignore any reference/note sent with cash.

PATCH /fees/payments/:id — amount, channel, and/or reference.
  Switching to bank requires a reference (new body or existing note).
  Switching to cash clears note.

Payment modal (FeePaymentTab, all clients). Replace “Note (optional)”
with:

  Method     [ Cash ]  [ Bank ]     required, no silent default
  Reference number                   shown and required ONLY if Bank
                                     placeholder e.g. 001GC0
                                     free text (not digits-only)

Confirm is blocked until Cash or Bank is selected, and until Bank
has a non-empty reference.

Payment history (FeeRecordView) and fee statement PDF, each line:

  Amount · Cash|Bank · date/time · Reference (bank) or — (cash)

Edit payment: same Cash/Bank control; Reference field appears for
Bank. Saving a bank row without a reference is refused.

PART E — Desktop sync: absence_days.student_id NOT NULL
========================================================

Error still seen on pull/snapshot:

  NOT NULL constraint failed: attendance_absence_days.student_id

Same class of bug can hit attendance_records,
attendance_student_day_scans, attendance_fee_payments,
attendance_fee_discounts when a child row arrives before (or without)
its student.


10. Cause
---------
toWirePayload replaces numeric FKs with UUIDs. If the student is gone
or not yet in local SQLite, student_uuid is null/unresolved.

fromWirePayload (sync/identity.js) then:

  • uuid missing  → sets student_id = null
  • uuid present but lookupIdByUuid returns null
      → may skip missing_fk when a leftover numeric id exists, then
        overwrites student_id with null anyway

applyMutation INSERTs that row. SQLite NOT NULL fires. engine.js
re-throws (only unique errors are skipped), and the whole pull fails.


11. Fix (shared apply path — desktop pull AND cloud push)
---------------------------------------------------------
fromWirePayload, for every required FK (student_id, academic_year_id,
and other NOT NULL FKs in TABLE_FKS):

  1. Resolve uuid → local id.
  2. If unresolved, throw { code: 'missing_fk', fk, uuid }.
     Never write null into a NOT NULL column.
  3. Never copy a foreign numeric id from the wire (cloud id ≠ local id).
  4. Optional FKs only (discount class_id XOR student_id) may stay null
     when that side is unused.

applyMutation / engine applySnapshot / pullChanges / cloud push:

  On missing_fk:
    Skip this row. Do not abort the batch.
    Desktop: leave last_pull_cursor unmoved only if you must retry
    the same change; preferred: skip orphan, advance cursor, log
    [sync] skip table uuid missing_fk:student_uuid
  On SQLITE_CONSTRAINT_NOTNULL / 23502:
    Treat like missing_fk: skip, log, continue. Never surface this
    as a fatal sync error to the UI.

Orphans (absence_days whose student was deleted): skip forever.
Cloud snapshot builder: omit child rows whose parent uuid lookup
returns null, so they are not sent.

Order already has attendance_students before attendance_absence_days.
Keep UPSERT_ORDER. After applying a chunk, one retry pass for rows
skipped with missing_fk in that chunk (student may have landed
earlier in the same snapshot). If still unresolved, skip.

Do not ALTER absence_days.student_id to nullable.


12. UI
------

banner. Only real failures (network, auth, unique corruption) show.
Log skipped counts in the desktop log, not a modal.

13. Search API (routes.js GET /fees/students/search)
----------------------------------------------------
SQL must run on Postgres and SQLite:

  dialect.convertPgToSqlite: rewrite ILIKE to
    LIKE … COLLATE NOCASE
  (SQLite has no ILIKE; without this, behaviour is not the same.)

  SELECT aliases stay snake_case. Mapper is defensive:

    fullName:  r.full_name  ?? r.fullName  ?? ''
    className: r.class_name ?? r.className ?? null
    classId:   r.class_id   ?? r.classId   ?? null
    barcode:   r.barcode
    id:        r.id

  Never return a hit with an empty fullName if the DB has a name.
  If both casings are missing, skip the row (do not push a blank card).

Same mapper for any other student-summary endpoint the discount or
payment pickers use.
